# F9. Manual editor and replayable state

Date: 2026-10-24. This note records an optional offline editor and a replay file. `--editor` and `--state` are off by default. A default run writes no `editor.html` and no `state.json`. `--id-col` stays `analysis_IID`. `--group-col` stays `Dong_Grp`. `--palette` stays `science`.

## What the command writes

`--editor` writes `editor.html` and `state.json` in the output directory. The page is one file. It uses the same JSON escaping as the HTML panel, and the same rule that a script, link, or img tag, and a src or href attribute, must not contain `http` or `//`. The drawing functions are the panel functions. The page adds controls. The document title is `qbar editor`.

`state.json` is written only together with `--editor`. A run that passes `--state` and does not pass `--editor` reads a state file and does not write a new one. `--editor` together with `--state` is allowed. The figure is the replay, and the new `state.json` is built from that result, including any column swaps already in the file.

## State schema

The object schema name is `qbar-state`. `schema_version` is the integer 1. A boolean is rejected. The file is UTF-8 JSON, indent 2, with non-ASCII characters as `\u` escapes, and a trailing newline. Keys are written in the order below, not sorted.

| Key | Meaning |
| --- | --- |
| `schema` | The text `qbar-state` |
| `schema_version` | Integer 1 |
| `qbar_version` | Package version string. This tree is `0.2.0.dev0` |
| `git_commit` | The current commit when git can see it, otherwise `unknown`. Replay does not compare this field |
| `inputs` | One object per input file. See the privacy rule |
| `k` | K values, low to high |
| `align_method` | Align method string, for example `greedy` |
| `plot` | Options recorded so a later reader can see how the figure was built. Replay ignores this object |
| `group_order` | Group names in first-appearance order along `sample_order` |
| `sample_order` | Display order as an explicit iid list. This is the order written to `order.tsv` |
| `sample_groups` | Group label for each iid in `sample_order`. The editor uses it to keep a move inside one group |
| `clusters` | For each K, `name` and `colour` in display order. Column 0 is the bottom of the stack |
| `swaps` | For each K, a permutation. Display column `i` comes from aligned column `swaps[i]` |
| `alignment_overridden` | True after a column swap. A non-identity permutation with this flag false is an error. True with an identity permutation is allowed |

`inputs` objects have `role`, `name`, and `sha256` only. `clusters` and `swaps` use the K value as a string key. Each cluster entry is `name` and `colour`. `colour` is `#rrggbb` after `norm_hex` on replay.

`plot` keys, in write order: `align`, `align_mode`, `anchor_group`, `align_groups`, `qmax`, `jaccard_set`, `jaccard_cut`, `palette`, `color_lock`, `order_mode`, `group_order_flag`, `within`, `rest_name`, `blocks`, `q_format`, `replicates`, `mode_sim_cut`, `width`, `bar_height`, `title`. `group_order_flag` is the command's `--group-order` value. It is not the sample group list.

## Privacy rule

Each input is stored as a base name plus the SHA256 of the file bytes. The directory is not stored. The command-line path is used only while hashing and matching, and it is left out of `state.json` and out of the state embedded in `editor.html`.

Roles are `q` for the matrix files, in the order they were collected, then `fam`, `ids`, or `ind` for the one sample-id source, then `groups` when a groups file was given. `ind` is its own role.

## Replay rules

`--state PATH` reads the JSON after the usual alignment and after the usual sample order and colours. It then replaces the sample order, group order, column swaps, names, and colours.

The recorded SHA256 values are matched to the files on the command line by role and by order within that role. The base name may differ. A hash mismatch names the command-line path: `State SHA256 does not match PATH.` A count mismatch names the command-line paths for that role, joined by a comma and a space, or `(none)` when the command has no file of that role: `State has STATE_N ROLE files and the command has CLI_N (PATH).`

`k` must equal the command's K list. Otherwise: `State K is STATE_K and the command line K is CLI_K.` `align_method` must equal the command. Otherwise: `State align method is STATE_METHOD and the command line align method is CLI_METHOD.` A missing `k` or `align_method` is `State is missing FIELD.` Other `plot` values are not compared.

`sample_order` is the full display order. An id that is not in the sample list is `State sample order names unknown id IID.` An id that is absent from the list is `State sample order is missing id IID.` A repeated id is `State sample order repeats id IID.` The first offender stops the run.

When `group_order` is present it must be the order in which groups first appear along `sample_order`. An unknown name, a missing name, or a different sequence is an error and names the group or both sequences. When `sample_groups` is present it must be the same length as `sample_order`, and each label must match the groups file for that id. The message names the id and both group labels.

`swaps` for a K is a permutation of `0 .. K-1`. Display column `i` is aligned column `p[i]`. An identity permutation leaves the aligned matrix as it was. A non-identity permutation copies columns, moves the raw-column index and the palette colour with the data, and then cluster colours replace those hex values. Owners are computed again after the swap. `alignment_overridden` false with a non-identity permutation is `State alignment_overridden is false but K=K swaps columns.`

Cluster colours are checked with `norm_hex`. A missing `#` is added. The text must be 7 characters. The stored colour is lowercase. A bad length, or a 7-character value that is not hex, is `A color must be written as #rrggbb, got TEXT.` The same message is used for `--color` and `--color-file`. A repeated colour at one K is `State K=K repeats a colour.` When a K has no cluster list, names stay `C1` through `CK` and colours stay the palette colours after the swap.

Where a swap moves columns of a K, the alignment scores for every step that uses that K are computed again from the columns that are drawn. The None that marks the unmatched column moves with that column. The report row for the column now drawn in that place has `matched_from` `new` and similarity `NA`. Each other column is scored against the previous column at the same display index when that previous column exists. A matched column that the swap moved past the previous K is scored against the previous column it was aligned to, and `matched_from` names that column. For greedy and hungarian the score is the Pearson r of that pair, so `similarity` and `pearson` in the same report row are that value. `align.tsv` lists those scores in display order. A trailing unmatched column is omitted, which is the text written when nothing has moved it. If the unmatched column is not last, its place in that list is the token `NA`, in the same position as the report row marked `new`. A dendrogram, and the linkage files that go with it, are built again from the displayed matrix when that K was the clustering K. The leaves are placed on the sample order the state already chose. A K that was not swapped keeps its scores and its tree. An identity permutation does not rebuild them.

A column name that differs from the positional `C1`, `C2`, ... label is used in the PNG, PDF, and HTML legends for that K. The `C` column of `perm_K*.tsv` stays the positional label. With no state, legends stay the previous text.

`--state` with `--order-file` is `--state cannot be combined with --order-file.` `--state` with `--color` or `--color-file` is `--state cannot be combined with --color or --color-file.` Those checks happen before the file is applied. English text is in `qbar.messages`, and each key has a short Chinese line.

`apply_state(config, state)` and `state_from_run(result)` are in `qbar.state`. `config` carries `iids`, `groups`, `aligned`, `perm`, `hexes`, `order`, `align_method`, and `language`. `state_from_run` takes a dict. `RunResult` does not carry sample ids or input hashes, so the command builds that dict itself.

## Editor operations

The page embeds three JSON scripts: `qbar-data` (the panel payload, used for the first paint), `qbar-base` (Q in input order, before a column swap, so later swaps compose), and `qbar-state`. Pure functions live in the drawing script and do not read the DOM. `applyEdit(state, op)` returns a new state. `bootEditor` returns at once when `document` is undefined, so a node harness can load the functions.

| Op | Fields | Effect |
| --- | --- | --- |
| `move` | `iid`, `index` | Move that sample inside its own group. `index` is the destination index in the group after the sample is removed, from 0 |
| `reorder_groups` | `groups` | A permutation of `group_order`. Samples keep their within-group order |
| `swap` | `k`, `i`, `j` | Exchange display columns `i` and `j` at that K. `k` may be omitted when the state has one K. The permutation entries and the cluster entries both move. `alignment_overridden` becomes true, including when `i` equals `j` |
| `rename` | `k`, `column`, `name` | Set the cluster name at that column |
| `colour` | `k`, `column`, `colour` | Set the colour string. The op `color` is accepted as well |

The controls are: Sample, Index in group, Move in group, Group, Group up, Group down, K, Column from 0, Other column, Swap columns, Name, Rename column, Colour, Set colour. Every control writes the in-page state and redraws the canvas. A rejected edit leaves the state unchanged and writes the message under the buttons.

## Downloads

Three buttons download files. The browser uses a blob URL. The page source has no `http` address.

`order.txt` is one iid per line, with a trailing newline. `--order-file` already accepts that form.

`colours.tsv` has no header. Each line is the cluster name, a tab, and `#rrggbb`. Lines run from low K to high K, and within a K from the bottom of the stack. `parse_colors` splits on whitespace and joins the first two fields as `name=#rrggbb`. A name that is `C` or `c` plus digits is a column colour, 1-based. Any other name is a group colour. The same name can occur once per K, and the last line wins in `parse_colors`. Per-K colours in `state.json` are the replay source. A name that contains a space does not round-trip through `parse_colors`, because the join keeps the first token only.

`state.json` is the replay file. The button uses `JSON.stringify` with indent 2. The file written by `--editor` uses ASCII escapes. When the content is ASCII, both parse to the same object.

## Manual click protocol

This check did not open a browser. The steps below are the manual check for the page.

1. Open `editor.html` from disk. No server is required. The canvas shows the same panel as the PNG, lowest K at the top, column 0 at the bottom.
2. Choose a sample and an index in its group, then click Move in group. That sample moves inside its group. An index outside the group prints `index` and the bars stay put.
3. Choose a group and click Group up or Group down. The group's samples move as a block and keep their order inside the group. Group up on the first group does nothing.
4. Choose K and two columns numbered from 0, then click Swap columns. Those two columns exchange, and their names and colours move with them.
5. Type a name and click Rename column. The legend for that column at that K uses the new name. The column index is Column from 0.
6. Type a colour such as `#4470b7` and click Set colour. The same column index is used. Replay checks the colour with `norm_hex`.
7. Click Download state.json, Download order.txt, and Download colours.tsv.
8. Replay with the same Q files and the same id file, plus `--state` and the downloaded `state.json`, and without `--order-file`, `--color`, or `--color-file`.
