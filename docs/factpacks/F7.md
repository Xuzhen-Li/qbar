# F7. Cluster tracking across K

Date: 2026-10-23. This note records an optional table and a static figure of membership weight between aligned columns at consecutive K. `--id-col` stays `analysis_IID`. `--group-col` stays `Dong_Grp`. Both weights are qbar's own definitions, not pong's or Clumppling's drawing. The figure is membership weight, not descent. Ties are drawn. It does not force a tree.

`parent_shares` and `split_parent_of` live in `src/qbar/report.py`. The member-set Jaccard is `jaccard_matrix` in `src/qbar/align.py`. The edges live in `src/qbar/flow.py`. The figure lives in `src/qbar/plot_static.py`. The drawing module is imported when a run starts. `flow.py` does not import Pillow.

## Flags

`--cluster-flow` is `none` or `sankey`. The default is `none`. `none` writes no flow file. `sankey` writes `cluster_flow.tsv`, `cluster_flow.png`, and `cluster_flow.pdf`.

`--flow-weight` is `share` or `jaccard`. The default is `share`. The weight is read only when `--cluster-flow` is `sankey`. Any value other than `share`, while `--cluster-flow` is `none`, exits with `--flow-weight jaccard requires --cluster-flow sankey.` The Chinese sentence is `--flow-weight jaccard 需要 --cluster-flow sankey。` `--flow-weight share` together with `--cluster-flow none` is the default and runs. The parser stores the same `share` whether the flag was typed or left alone, so the check is the stored value.

## Weights

A step is one pair of consecutive K. Sorted K must increase by 1. A gap exits with the same message as `align_qs`. K = 2 followed by K = 4 says `Cross-K alignment requires consecutive K. Missing K=3`. The Chinese sentence names the same missing K. `--cluster-flow sankey` with `--no-align` exits with `--cluster-flow sankey needs alignment across K; remove --no-align.` The Chinese sentence is `--cluster-flow sankey 需要跨 K 对齐；去掉 --no-align。` A gap is reported first, including when `--no-align` is set. One K, with alignment left at its default, has no step.

For each destination column whose masked sum is greater than 0, one edge is stored for every source column with weight strictly greater than 0. There is no tolerance. A tie keeps every positive edge. `split_parent_of` is not consulted, so the lower index does not drop the other edge. A source that meets two destinations is two edges. Edges are ordered by K, then destination column index, then source column index.

`share` is `parent_shares` of the destination column on the alignment mask: `sum_i (new_i * prev_ic) / sum_i new_i`. The mask is `meta[K_to]["mask"]`, the mask the alignment report uses. When that entry is missing, every row is used. The weights on the edges into one destination sum to the sum of its `parent_shares`. That sum is 1 when each previous masked row sums to 1 and the destination column's masked sum is greater than 0. For `--align-method pong` the alignment report stores the alignment parent, while the flow still draws every positive share.

`jaccard` is `|A intersect B| / |A union B|` on `member_sets`. An empty union is 0. `dominant` is the row argmax, and a tie keeps the lowest index. `threshold` is `q >= cut`. The defaults are `dominant` and `0.5`, the same defaults as `--align-method jaccard`. The CLI passes `--jaccard-set` and `--jaccard-cut` even when the align method is another name. The `method` column of the table remains the align method.

A destination column whose masked sum is <= 0 has no edges, for either weight. That is the same cutoff as `split_parent_of`. It also drops a dominant-set Jaccard that would be positive only because every tied zero falls on the lowest index.

## low_confidence

`low_confidence` on an edge is the destination column's flag from the alignment report. The match is `K_to` plus the aligned label `C1`, `C2`, and so on. The source column's flag is left unused. A matched column carries `yes`, `no`, or `NA` from that report's similarity cut. The new column's report flag is `NA`, so every edge into the new column is `NA`. When `--align-report` is off, or this run writes no report, every edge is `NA`. Two report rows with the same key keep the first row.

## Table

Columns, in order: `K_from`, `col_from`, `K_to`, `col_to`, `weight`, `weight_definition`, `method`, `low_confidence`.

`weight` uses `%.6f`. `weight_definition` is `share` or `jaccard`. `method` is the align method. Labels are the aligned column labels. The file is UTF-8 with LF newlines.

## Figure

`cluster_flow.png` and `cluster_flow.pdf` are 960 by 640, white, RGB. The PDF uses the same Pillow save as the bar plot, resolution 150. Two runs on the same machine write the same PNG bytes. PDF bytes match after `/CreationDate` and `/ModDate` are removed, which is the rule in `tools/compare_outputs.py`.

Each K is one column of nodes. C1 sits at the bottom, as in the bar. Node height is the mean of that aligned column over every row, times one scale shared by every K. That mean is the sum over all rows divided by the row count. A negative or non-finite mean is drawn as height 0. The mean uses every row, including people outside the alignment mask, because the bar draws every person. Node colours are the hex list the bar uses for that K.

Band thickness is the weight times the sum of the destination column over the rows used for that step, divided by the row count, times the same scale. The rows used for that step are the alignment mask. With no mask, every row is used, and the thickness equals the weight times the all-row mean times the scale. Share weights into one destination sum to at most 1, so those bands fill at most the masked part of that node. Jaccard weights are not a partition of the destination, so a stack of bands can still run past the node. A thickness that is above 0 and below half a pixel is drawn as 1 pixel, so a positive tie stays visible. Bands stack from the bottom of each node. A lower column index sits closer to the bottom. The band colour is the source column colour mixed with white, 65 percent source. Nodes are drawn after the bands, in the full column colour.

The axis title and the legend title are both `membership weight`. The legend also says `Node height is the mean membership of that column.` and `Band thickness is weight times the destination column sum over the rows used for that step, divided by all rows.`
