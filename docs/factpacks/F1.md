# F1. Hierarchical clustering across samples or groups

Date: 2026-10-23. This note records optional hierarchical ordering of every row, or of groups, a SciPy linkage table, and a dendrogram above the bars. `--id-col` stays `analysis_IID`. `--group-col` stays `Dong_Grp`. The leaf order is SciPy's. The dendrogram geometry is qbar's own. The distance between groups is the mean Q row, which is qbar's own. A run over the byte cap stops before the distance vector. Rows are not dropped and are not replaced by a sample.

`linkage_matrix`, `hclust_order`, and `group_hclust_order` live in `src/qbar/order.py`. The dendrogram lives in `src/qbar/plot_static.py`. The drawing module is imported when a run starts. `order.py` does not import Pillow. The dendrogram does not call `scipy.cluster.hierarchy.dendrogram` and does not use matplotlib.

## Flags

`--order-mode` is `within`, `global-hclust`, or `group-hclust`. The default is `within`. `within` orders inside groups and writes no linkage file, including when `--within` is `hclust`.

`global-hclust` builds one tree over every row at `--hclust-k`, with `--hclust-dist`, `--hclust-linkage`, `--hclust-pre`, and `--hclust-olo`. Those options follow `hclust_order`. A constant row under correlation has `1e-12` added to column 0. Ward requires euclidean. A non-finite distance is an error. Fewer than 2 rows keeps the input order. `--hclust-pre dominant` splits by the highest column, lowest index on a tie, and clusters inside each block. Groups may occupy several spans. `spans_of` records a span wherever the label changes.

`--blocks` on `global-hclust` or `group-hclust` is ignored, and the run warns. `--within` and `--within-group` are ignored on `global-hclust`. That warning is printed when `--within` is not `iid` or when `--within-group` is set. `--order-file` with an order mode other than `within` is an error, before any output file.

`group-hclust` keeps each group contiguous. `--group-order` is `input` or `hclust`. The default is `input`. `input` is the order groups first appear in the groups vector. That first-seen order is kept when it differs from alphabetical order and from `--blocks`. `hclust` orders groups by one tree on the mean Q row of each group, at the same K, with `--hclust-dist`, `--hclust-linkage`, and `--hclust-olo`. A single group keeps that input order and does not build a between-group distance vector. Inside each group, the order is the existing `--within` choice. `--group-order hclust` with any mode other than `group-hclust` is an error. The message is `--group-order hclust requires --order-mode group-hclust.`

`--dendrogram` is `none` or `top`. The default is `none`. `top` is allowed with `global-hclust`, and with `group-hclust` when `--group-order` is `hclust`. With `--order-mode within`, or with `group-hclust` and `--group-order input`, `top` is an error. The message is `--dendrogram top needs --order-mode global-hclust, or --order-mode group-hclust with --group-order hclust.`

## Byte cap

`--hclust-max-bytes` defaults to unset. The condensed distance vector for N rows has `N*(N-1)/2*8` bytes when N is at least 2, and 0 otherwise. N = 10000 needs 399960000 bytes. N = 100000 needs 39999600000 bytes. N = 10 needs 360 bytes. N = 32768 needs 4294836224 bytes. N = 32769 needs 4295098368 bytes. N = 40000 needs 6399840000 bytes. The count is a Python integer. The matrix is not allocated to compute it.

The run refuses when the byte count is greater than the cap. Equality is allowed. `0` means no cap. A negative value is an error: `--hclust-max-bytes must be 0 or greater, got %(cap)s.` The refusal message names N, the byte count, and the cap, and it names within-group clustering and `--hclust-pre dominant`: `Hierarchical clustering of N=%(n)s needs %(nbytes)s bytes (N*(N-1)/2*8), which is above --hclust-max-bytes %(cap)s. Use within-group clustering or --hclust-pre dominant.`

When the flag is omitted, `global-hclust` uses 4294967296 for the all-rows vector, and `group-hclust` uses 4294967296 for the between-group vector. That is 4 GiB. N = 32768 is under it. N = 32769 is over it. Within-group trees have no cap, including `--within hclust` under `--order-mode within` and the trees inside `group-hclust`. A dominant block that does not contain every row also has no cap when the flag is omitted, so `--hclust-pre dominant` does not build the all-rows vector. A positive value applies to every tree, including each group's N and each dominant block. `--order-mode within` has no cap when the flag is omitted. The default run is unchanged.

The check runs before SciPy builds the distance vector, and before the output directory is created. A refusal writes no output file.

## Linkage files

The new modes write linkage tables. `--order-mode within` writes none.

`global-hclust` writes `linkage_global.tsv` when the order is one tree over every row. `--hclust-pre none` is that tree. A header-only file is written when N is below 2. `--hclust-pre dominant` writes the file only when one block contains every row. Several blocks are not one SciPy matrix, and that run does not build the all-rows vector.

`group-hclust` with `--group-order hclust` writes `linkage_between_groups.tsv`. The leaves are the groups in input order, which is first appearance. One group writes a header-only file.

When the within ordering is `hclust`, `group-hclust` also writes `linkage_group_<n>.tsv` for each group with at least 2 rows whose clustering is one tree covering that group. `n` is the 1-based group index in input order. There is no zero padding. A dominant forest inside a group does not write that group's file.

Whenever a between-groups file or a group-indexed file is written, the run also writes `linkage_index.tsv`. Columns: `index`, `group`. `index` is 1-based. It is the `n` in `linkage_group_<n>.tsv`. It is also one more than the 0-based SciPy leaf in `linkage_between_groups.tsv`: leaf `j` is the group with index `j + 1`. The index lists every group in first-appearance order, including a group of one row that has no `linkage_group` file. Group names are never used in file names.

Linkage columns, in order: `row`, `idx1`, `idx2`, `distance`, `count`. `row` is the 0-based merge index. `idx1` and `idx2` use SciPy's coding: observations are `0 .. n-1`, and the cluster formed at that row has id `n + row`. `distance` uses `%.6f`. `count` is the integer number of observations. The file is UTF-8 with LF newlines.

## Dendrogram

`--dendrogram top` draws with Pillow above the bars on `bar_K*.png` and `panel.png`. Other figures, including the cluster-flow figure, are unchanged. The canvas grows by 160 px when `--dendrogram top` draws a tree. Width stays `left + bar width + gap + legend + 16`.

The dendrogram part is 160 px tall. The scale is 160 divided by the largest merge distance on that figure. The figure prints that distance at the top-left of the dendrogram area as `max distance 1.124`, with three digits after the decimal (`%.3f`). One pixel of height is that printed distance divided by 160. A largest distance of 0 draws every segment on the baseline, against the bars, and does not divide by zero. A merge of distance `d` is a horizontal segment at `y_bottom - d * scale`, with vertical segments down to the two children. An internal node's x is the midpoint of its two children. The same rule is used for a tree of samples and for a tree of groups.

A sample leaf at rank `i` among `n` samples sits at `left + (i + 0.5) * bar_w / n`. `left` is 56, the same `BAR_LEFT` the bars use. For `n = 4` and `bar_w = 400` that is `56 + (i + 0.5) * 100`. A group leaf sits at the centre of that group's span, the same integer as the group label: `px0 = left + int(start * bar_w / n)`, `px1 = left + int(end * bar_w / n)`, and the centre is `(px0 + px1) // 2`. The ink is RGB (31, 41, 55), width 1. Several layers, from a dominant split, share one scale, 160 divided by the largest merge on the figure, and one baseline. Group boundary lines start at the bars.

On the N = 10000 timing inputs, the default panel is 2373 by 650. With the 160 px dendrogram, the `global-hclust` panel is 2373 by 810 and the `group-hclust` panel is 2384 by 810. The group figure is 11 pixels wider because the legend names the five groups. Read the scale from the printed `max distance` line: divide that number by 160.
