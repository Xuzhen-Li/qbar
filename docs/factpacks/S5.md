# S5. Vector PDF and SVG

Date: 2026-10-24. This note records optional vector PDF and SVG output for the bar figures. The default is off. A default run keeps the PNG and the raster PDF and writes no SVG.

## What a vector file is

The raster PDF is one JPEG image of the PNG, saved by Pillow at resolution 150. A vector file draws the same geometry as `render`: bar rectangles, legend swatches, group labels, K labels, a title when one is set, and a dendrogram when `render` draws one. Coordinates stay in pixel units. One SVG user unit is one pixel. PDF points are 72/150 per pixel, so the page size equals the raster PDF page size. PNG files stay the same raster as today.

A bar is one rectangle per sample per column whose Q value is greater than 0. Adjacent rectangles of the same colour are not merged. The x position is `left + i * bar_w / n`. The width is `bar_w / n`, plus 0.5 px on every sample except the last one in the row. That extra width extends right, into the next sample. Each stacked segment except the one that reaches the top of the bar is 0.5 px taller, extending up into the next segment. The outer outline of the bar block stays the same. The overlap is there so viewers do not draw a seam between abutting edges. Column 0 is the bottom of the stack. Legend swatches are paths. The SVG page background is a path. Those paths are not bar rectangles. A dendrogram is lines plus its distance label.

## File names

`--vector` is `off`, `pdf`, `svg`, or `both`. The default is `off`.

| Mode | `bar_K*.pdf` and `panel.pdf` | SVG | PNG |
| --- | --- | --- | --- |
| off | raster, same as before | not written | raster |
| pdf | vector, same file names | not written | raster |
| svg | raster | `bar_K*.svg` and `panel.svg` beside the PNGs | raster |
| both | vector | `bar_K*.svg` and `panel.svg` | raster |

A single K still has no panel. Cluster-flow, CV, and select-K PDFs stay raster. `--id-col` stays `analysis_IID`. `--group-col` stays `Dong_Grp`. `--palette` stays `science`.

`render_vector` in `qbar.plot_vector` takes the same arguments as `render`, plus the Q matrix on each row. Pillow is imported only inside the font helpers. The vector PDF bytes are written with the standard library and zlib.

## Cap and counting

The cap is 200000 rectangles in one vector file. The count is the number of bar rectangles that file would draw: Q cells greater than 0 in that file's rows. Legend swatches are not included. A count equal to the cap is allowed. A count above the cap stops the run. Every vector file is counted first. If any file is above the cap, no figure file from that run is written, including files that were under the cap. The error names each file that is above the cap, with that file's count and the cap.

The count is taken from the Q values after they are read. Saving draws with `%.6f` can turn a tiny value into 0, so `N * K` is an upper bound. Row order and column order do not change the count.

## Fonts

Vector output needs a TrueType file from `FONT_CANDIDATES`. If none of those files exists, the run stops. It does not fall back to a bitmap font.

On this machine the first existing file was Arial. The PDF embeds that file as `FontFile2` on a simple TrueType font. The encoding is WinAnsiEncoding. FirstChar is 32 and LastChar is 126. Each width is `int(round(getlength))` from Pillow `ImageFont.truetype(path, 1000)` for characters 32 through 126. The BaseFont on this run was `ArialMT`. The PDF has no CreationDate and no ModDate. The object order is fixed.

SVG text is a `<text>` element. The root `font-family` is the face name plus a generic fallback. This run used `Arial, sans-serif`. The file says `This file names the font and does not embed it.` There is no `@font-face` and no font file inside the SVG.

Vector PDF draws only ASCII text, characters 32 through 126. A drawn label outside that range is an error that names the label, and no file is written. SVG can contain that character. `both` uses the PDF check and writes nothing.

## Raster probe

One default demo `panel.pdf` was searched as bytes. `/DCTDecode` occurs once, `/CreationDate` once, and `/ModDate` once. `/FlateDecode`, `/Font`, and `/FontFile2` do not occur. The same search on one default timing `panel.pdf` found `/DCTDecode` and did not find `/Font` or `/FontFile2`.

One `--vector both` `panel.pdf` contains `/FontFile2` once, `/WinAnsiEncoding` once, and `/BaseFont /ArialMT`. It does not contain `/CreationDate`, `/ModDate`, or `/DCTDecode`. The matching `panel.svg` sets `font-family="Arial, sans-serif"` and says that the file names the font and does not embed it.

## Tests

From the repository root, `python -m unittest test_qbar.py` reported `Ran 240 tests in 8.063s` and `OK`. The parent commit had 230 tests.

A 2-sample, 2-column fixture writes one SVG `<rect>` per sample per column with nonzero height. The x positions equal `left + i * bar_w / n` from the renderer constants. Widths and heights include the 0.5 px overlap, computed in the test from that rule. The fills equal the perm hex values. A row that sums to 1.05 is clipped to the bar. A vector PDF has one `re` operator per bar rectangle, a MediaBox equal to the raster PDF page size, a `FontFile2` object, and no `/CreationDate`. Two vector PDF runs are byte identical. A count above a lowered cap exits and leaves no output directory. A count equal to that cap writes the SVG. A default run writes no `.svg`. `--vector off` matches the default figures and tables. A non-ASCII title is an error for vector PDF and for `both`, and SVG mode writes the character. A missing font file is an error. A dendrogram run still has one `<rect>` per positive cell and draws the tree as lines.

The only existing test edited for this change is `test_readmes_name_every_cli_option`. `--vector` is in its exemption set. It is documented in `docs/cli.md` and in this file. The READMEs do not name it.
