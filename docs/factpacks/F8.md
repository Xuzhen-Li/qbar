# F8. Groups, including data-driven groups

Date: 2026-10-23. This note records optional groups derived from an aligned Q matrix, or from PCA scores, written as a groups file. `--id-col` stays `analysis_IID`. `--group-col` stays `Dong_Grp`. The group names are qbar's own. A run with `--auto-groups none` writes no new file. Auto groups do not replace `--groups` in the figure order.

`auto_groups` and `read_plink19_eigenvec` live in `src/qbar/autogroups.py`. The all-rows byte cap is the F1 helper `cap_for_tree` in `src/qbar/order.py`. `autogroups.py` does not import Pillow. The drawing module is still imported when a run starts.

## Flags

`--auto-groups` is `none`, `major`, `threshold`, `hclust`, or `kmeans`. The default is `none`. `none` writes neither `groups_auto.tsv` nor `groups_auto_summary.txt`.

`--auto-k` is the K whose aligned matrix supplies `max_q`, `top_column`, and, unless `--pca` is set, the rows that are clustered. The default is unset, which means the largest K.

`--admix-cut` is used only by `threshold`. The default is `0.5`. The accepted interval is above 0 and at most 1. `0` is an error. `1` is allowed. A row is `admixed` only when `max(q)` is strictly below the cut. A row whose maximum equals the cut is named by its top column.

`--auto-g` is required for `hclust` and `kmeans`. It must be an integer greater than or equal to 1. A value greater than the row count is an error, before a distance vector is built.

`--auto-seed` defaults to `0`. It is used only by `kmeans`.

`--pca` is a PLINK 1.9 `.eigenvec` path. It is accepted only by `hclust` and `kmeans`. `--pca-n` is required with it. `--pca-n` must be an integer greater than or equal to 1, and it must be at most the number of score columns in the file. There is no default count.

A stored default is allowed while `--auto-groups` is `none`. Any other auto flag is an error, the same rule as `--flow-weight` while `--cluster-flow` is `none`. `--auto-groups none --admix-cut 0.5 --auto-seed 0` runs and writes no groups file. `--auto-groups none --admix-cut 0.6` exits with `--admix-cut 0.6 requires --auto-groups threshold.` The Chinese sentence is `--admix-cut 0.6 需要 --auto-groups threshold。` `--auto-k` has no stored number, so any `--auto-k` while the mode is `none` is an error. `--admix-cut` other than `0.5` requires `threshold`. `--auto-g` requires `hclust` or `kmeans`. `--auto-seed` other than `0` requires `kmeans`. `--pca` requires `hclust` or `kmeans`. `--pca-n` without `--pca`, and `--pca` without `--pca-n`, are errors.

`--hclust-pre` is not used by `--auto-groups hclust`. The tree always uses every row. If `--hclust-pre` is not `none`, the run warns and still clusters every row. `--hclust-dist`, `--hclust-linkage`, and `--hclust-olo` are followed, including when the rows are PCA scores.

## Methods

Each rule below is qbar's own.

`major` names row `i` as `C{c+1}`, where `c` is `argmax` of that row. A tie keeps the lowest index.

`threshold` uses that same name when `max(q)` is greater than or equal to `--admix-cut`. When `max(q)` is below the cut, the name is `admixed`. The top two columns are not pasted into the name. On `[[0.9, 0.1], [0.2, 0.8], [0.5, 0.5]]`, cut `0.5` gives `C1`, `C2`, `C1`. Cut `0.6` gives `C1`, `C2`, `admixed`.

`hclust` builds one linkage with `linkage_matrix` and cuts it with `scipy.cluster.hierarchy.fcluster(Z, t=g, criterion='maxclust')`. The run checks that this cut returns exactly `--auto-g` groups. SciPy's `maxclust` forms no more than `t` clusters. When equal merge distances are cut together it can return fewer. qbar then stops, names the counts, and writes no output file. Three identical rows with `--auto-g 2` take that path: `fcluster` returns one group. There is no second cut that ignores the tie. Groups are then renamed `G1`, `G2`, ... by first appearance in input row order.

The byte cap is applied inside `linkage_matrix`, before SciPy builds the distance vector. It is the F1 all-rows resolution: an omitted `--hclust-max-bytes` uses 4294967296, `0` means no cap, and a positive integer is that cap. N = 4 needs 48 bytes, so a cap of 1 refuses. N = 10000 needs 399960000 bytes, which is under 4294967296.

`kmeans` calls `scipy.cluster.vq.kmeans2` with `minit='++'` and `missing='raise'`. One `numpy.random.default_rng(--auto-seed)` is passed as `seed` on each call, so the generator advances across restarts. The restart count is 10. That count is an arbitrary qbar choice. Each call leaves SciPy's own `iter` at its default, which is not the restart count. The kept labelling is the lowest within-cluster sum of squares. An equal sum keeps the earlier restart. The sum of squares is the sum of squared Euclidean distances from each row to its assigned centroid. The scores are not whitened. An empty cluster raises `ClusterError` and counts as a failed restart. There is no extra retry beyond the 10. If every restart fails, the run stops and writes no output file. Labels are renamed `G1`, `G2`, ... by first appearance, the same rule as `hclust`.

`kmeans2` accepts `seed` from SciPy 1.7.0 onward. This package already requires SciPy 1.9.0 or later (`scipy>=1.9.0`).

`max_q` and `top_column` always come from the aligned Q at `--auto-k`, including when the clusters were fit on PCA scores and including a row named `admixed`. `top_column` is `C1`, `C2`, and so on, with the lowest index on a tie. `max_q` is written with `%.6f`.

The `parameters` field is one ASCII string. `major` is `k=6;input=q`. `threshold` is `cut=0.5;k=6;input=q`, with the cut written by stripping trailing zeros from six decimal places. `kmeans` on PCA is `g=3;seed=0;restarts=10;input=pca;pca_n=10;k=6`. The same fields are used on Q, with `input=q` and no `pca_n`. `hclust` records `g`, `dist`, `linkage`, `olo` as `0` or `1`, `input`, `pca_n` when the input is PCA, and `k`. The trailing `k` records which aligned matrix supplied `max_q`.

## PCA input

Only the PLINK 1.9 `.eigenvec` layout is read: no header, whitespace-separated, FID, IID, then scores. PLINK 2.0 and smartpca `.evec` are not read. A first line that starts with `#`, that has fewer than three fields, or whose score cells are not finite numbers, stops with a message that only this layout is read. A later non-numeric score is a different error. Blank lines are errors. Rows are not skipped. IID is the match key. FID is kept on the line and is not used for the match. A duplicate IID is an error. An id in the Q matrix that is missing from the eigenvec is an error. Extra eigenvec rows are ignored. The summary records that count, including zero, as `eigenvec_rows_ignored`.

The score matrix has one row per Q id, in Q order, and `--pca-n` columns. Those columns are the leading score columns.

## Files

`groups_auto.tsv` columns, in order: `id`, `group`, `method`, `parameters`, `max_q`, `top_column`. The header names `id` and `group` are what `load_groups` reads when `--id-col id` and `--group-col group` are set. The file is UTF-8 with LF newlines.

`groups_auto_summary.txt` lists group sizes in first-appearance order, then the mean Q of each group's rows at `--auto-k`. Means use `%.6f`. It then contains this sentence on its own line:

`Groups derived from Q are for display and ordering. Using them as evidence for the same Q is circular.`

That sentence is written for every method, including groups fit on PCA scores. When `--groups` was given, the file also has a contingency table of counts. Rows are the auto groups in first-appearance order. Columns are the known groups in first-appearance order. The rest name is always a column. If that name never appears, it is last. Zeros are written. There is no adjusted Rand index. The Hubert and Arabie 1985 PDF was not quoted, so the formula is not coded. Crossref: Lawrence Hubert and Phipps Arabie, Comparing partitions, Journal of Classification 2(1):193-218, DOI `10.1007/bf01908075`, issued 1985-12.

`kmeans` also records `kmeans_whiten` as `no`, `kmeans_restarts` as 10, and `kmeans_failed_restarts`. `hclust` records `hclust_cut` as `fcluster maxclust`.

## Tests

From the repository root, `python -m unittest test_qbar.py` reported `Ran 225 tests in 6.193s` and `OK`. The parent commit had 216 tests.

The hand matrix `[[0.9, 0.1], [0.2, 0.8], [0.5, 0.5]]` is `C1`, `C2`, `C1` under `major`. At cut `0.5` the third row is `C1`. At cut `0.6` the third row is `admixed` and the first row is `C1`. Cut `0` and cut `1.5` raise `SystemExit`. Cut `1` leaves a row of `[1, 0]` as `C1` and a row whose maximum is `0.6` as `admixed`.

Two `kmeans` calls with the same seed return the same labels. On two blocks of four rows, centred near `(0, 0)` and `(10, 10)`, the labels equal that partition after the `G1`, `G2` rename.

An `hclust` result on a five-row matrix equals `fcluster` on a linkage computed in the test with SciPy, after the test renames clusters by first appearance. The tied three-row matrix raises `SystemExit` and the message names `maxclust`. A cap of 1 on four rows raises before `pdist`. `--auto-g` above the row count also returns before `pdist`.

A written `groups_auto.tsv` reloads through `load_groups` with columns `id` and `group`, and the groups match. A hand contingency is `C1` against known `A`, `B`, `NA` as counts `1 0 1`, and `C2` as `0 1 0`. A run that omits `--auto-groups` does not create either new file. Passing the stored defaults does not create them either. With `--groups` set, `order.tsv` keeps the known labels.

The eigenvec tests use a fixture written in the test, with invented ids. The reader returns scores in the requested id order and counts extra rows. A duplicate IID, a missing id, a header line, a line that starts with `#`, a later non-numeric score, and `--pca-n` past the score columns each raise `SystemExit`. `major` with `--pca` raises `SystemExit` and does not create the output directory. Help text for the new flags is ASCII. `--id-col` stays `analysis_IID` and `--group-col` stays `Dong_Grp`.
