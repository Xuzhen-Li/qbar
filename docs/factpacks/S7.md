# S7. YAML config

Date: 2026-10-24. This note records an optional YAML file of settings. `--config` is omitted by default. A default run writes no `config_resolved.json`. `--id-col` stays `analysis_IID`. `--group-col` stays `Dong_Grp`. `--palette` stays `science`.

## What

`qbar.config.load_config` reads one YAML mapping with `yaml.safe_load` and returns that mapping. PyYAML is imported only inside `load_config`. `qbar.state` stays the replay file and does not import PyYAML.

The extra is `qbar[config]`, declared as `PyYAML>=6.0.1`. The core install does not depend on PyYAML. If the import fails, `--config` exits and the message names `pip install "qbar[config]"`. The same sentence exists in English and in Chinese in `qbar.messages`. There is no `qbar[yaml]` extra.

## Keys

Keys are argparse dest names. A spelling with hyphens is accepted: leading `--` is stripped and `-` becomes `_`, so `align-method` and `--align-method` are `align_method`. Two spellings that land on the same dest are an error and the message names that dest.

The key `config` is rejected. The message says the file cannot set `config`. The key `state` is allowed. It is the dest of `--state`.

`--q` and `--outdir` may come from the file, and so may the other dests, including an id file. A dest the command line also set is taken from the command line. A repeated flag such as `--color` is not merged with the file: the command-line list replaces the file list.

YAML 1.1 treats unquoted `on`, `off`, `yes`, and `no` as booleans. Quote them when the field expects text. `color_lock: off` is a boolean and is rejected. `color_lock: "off"` is the string. A repeated YAML key of the same spelling keeps the last value. That is PyYAML `safe_load` on 6.0.3.

Paths in the file are resolved against the current working directory, the same way as paths on the command line. The directory that contains the config file is not used.

A `store_true` key set to true in the file stays true. The command line cannot turn it off. Those flags have no `--no-` form. The exception is `align`, which has `--align` and `--no-align`. Edit the file to turn the key off.

## Precedence

The command line, then the config file, then the parser defaults. A flag the user did not pass does not override a config value. A flag the user did pass wins even when the value equals the default. Presence comes from a second parse whose defaults are `argparse.SUPPRESS`, not from a comparison with the default.

`--state` is applied after that resolution. It replaces sample order and colours. If the file sets `align_method`, the command line does not pass `--align-method`, and the state names a different known method, the run uses the state method. `sources` for `align_method` stays `config`. A command-line `--align-method` must still match the state. If it does not, the run exits with the existing state message and writes no `config_resolved.json`.

`color`, `color_file`, and `order_file` from the file are ignored when `--state` is set. stderr prints one line naming those keys. `state_override` records each one as the config value and `used: state`. The top-level dest is the value the run used for that flag (an empty list or null). Passing `--color`, `--color-file`, or `--order-file` on the command line together with `--state` is still an error.

## Errors

| Case | What the message names |
| --- | --- |
| PyYAML is not installed | `pip install "qbar[config]"` |
| The file cannot be read | the path as given |
| The text is not YAML, including a non-UTF-8 byte | the file base name |
| A float that is not finite (`.nan`, `.inf`, `-.inf`, or the string `NaN`) | that dest |
| The same non-finite float on the command line when `--config` is used | that dest |
| The top level is not a mapping | the type that was read (`list`, `str`, `int`, `float`, `bool`, or `null`) |
| An unknown key | that key, as written |
| A key that is not a string | the type that was read |
| A value of the wrong type | the dest and the expected type (`int`, `float`, `str`, `bool`, or `list`) |
| A value outside the flag choices | the dest and `one of` the choices |
| The key `config` | that the file cannot set `config` |
| Two spellings of one dest | that dest |

A boolean is not accepted as an int or a float. An int is accepted for a float field. YAML null is accepted only when that flag's default is null and the flag is not required. `store_true` expects a boolean.

## Outputs

`config_resolved.json` is written in the output directory only after a successful run that was given `--config`. Keys are sorted. Indent is 2. The file ends with a newline. Non-ASCII characters are written as `\u` escapes. `NaN` is not allowed.

The object holds every argparse dest at the value the run used, plus:

| Key | Meaning |
| --- | --- |
| `sources` | dest to `cli`, `config`, or `default` |
| `config_file` | base name of the YAML file |
| `config_sha256` | SHA256 of the YAML bytes |
| `state_override` | present only when `--state` was also set |

`state_override.order` and `state_override.colours` are the text `state`. They are not the sample list. When the align method was taken from the state, `state_override.align_method` is an object with `config` and `state`. The top-level `align_method` is the method the run used. When a config `color`, `color_file`, or `order_file` was ignored, that key in `state_override` is an object with `config` and `used` set to `state`. File names in that object are base names. A non-finite float is rejected before the JSON is encoded.

`args.txt` is unchanged except that it includes `--config` when that flag was passed, with the path as typed. `qbar.api.run` does not read YAML and does not write `config_resolved.json`.

## Privacy rule

File-valued options in `config_resolved.json` are base names only. The directory is not stored. Those dests are `q`, `fam`, `ids`, `ind`, `groups`, `order_file`, `color_file`, `logs`, `logs_map`, `low_confidence_table`, `pca`, `state`, `outdir`, and `config`. An empty string stays empty. `config_file` is a base name. `config_sha256` is the digest of the file bytes.

The path as typed can still appear in `args.txt` and in the message for a file that cannot be read. It is left out of `config_resolved.json`.

## Example

```yaml
q:
  - k2.Q
  - k3.Q
ids: ids.txt
align_method: hungarian
outdir: out
```

The SHA256 of that text, including the final newline, is `ffb856ff17cf2e1a1f76d125891989da11f86cdaa841cb9f0fd01e0dfb3aac68`. A run with only `--config` on that file wrote `config_resolved.json` with `align_method` `hungarian`, `sources.align_method` `config`, `sources.q` `config`, `q` equal to `k2.Q` and `k3.Q`, and no `state_override`. No file-valued entry contained `/`.

## Tests

Twenty-six tests are in `ConfigTests`. The suite is 295 tests.

Without PyYAML the suite reported:

```
Ran 295 tests in 17.416s

OK (skipped=20)
```

The twenty skips are the tests that parse a YAML file. Six tests still run: the import of PyYAML is only inside `load_config`, the Chinese install message exists, a patched missing import names `pip install "qbar[config]"`, a default run writes no `config_resolved.json`, a non-UTF-8 file names its base name, and the Chinese `--config` help names an explicit flag.

With PyYAML 6.0.3 the same suite reported:

```
Ran 295 tests in 18.235s

OK
```

No test was skipped. A config-only `align_method: hungarian` matches the brute-force Hungarian permutation on the fixture where the greedy and Hungarian permutations differ. `--align-method greedy` on that file matches the greedy permutation. Passing the default palette and the default width on the command line beats the file. An unknown key and a bad type name the key. `config` is rejected. A hyphenated key maps to the dest. `--q` and `--outdir` may come from the file. Config plus `--state` records the align override and uses the state method. An explicit `--align-method` that differs from the state exits and writes no `config_resolved.json`. Invalid YAML names the base name and does not print a traceback. `.nan`, `.inf`, `-.inf`, the string `NaN`, and a command-line `--jaccard-cut nan` name `jaccard_cut`. Config `color`, `color_file`, and `order_file` with `--state` are ignored and recorded. Those same flags on the command line still error. A relative path in the file is opened from the working directory.

A default demo matches the previous baseline. No file differed. All 12 stderr rows are identical. The demo did not pass `--config`, so it wrote no `config_resolved.json`.
