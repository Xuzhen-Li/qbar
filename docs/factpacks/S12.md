# S12. Exports for other tools

Date: 2026-10-24. `--export` can write files for CLUMPP, DISTRUCT 1.1, and pong. The default is `none`, so a default run writes no `export` directory. `--id-col` stays `analysis_IID`. `--group-col` stays `Dong_Grp`. `--palette` stays `science`. No new dependency.

DISTRUCT note: Rosenberg, Molecular Ecology Notes 4:137-138. DOI `10.1046/j.1471-8286.2003.00566.x`. Manual: `https://rosenberglab.stanford.edu/software/distructManual.pdf`.

## Flag

`--export` is one string, not a repeating flag. `none` writes nothing. `clumpp`, `pong`, and `clumpp,pong` are the other values. Spaces around commas are ignored. A repeated name is kept once. `none` together with another name is an error. An empty string is an error, the same error as an empty element such as `clumpp,`. Any other token is an error, and the message shows the value. The config key is `export`, the same string. It is not a file path, and it is not a list. No new file-valued config dest was added.

`clumpp` writes `<outdir>/export/clumpp/`. `pong` writes `<outdir>/export/pong/`. Asking for both always writes `clumpp` and then `pong`. The order of the names does not change the bytes.

Rows are the plotted samples, in bar order. An alignment mask does not drop rows. Values are copied with `%.6f`. They are not divided by the row sum.

With `--replicates`, each K file is the aligned matrix. When that K has more than one Q file, that matrix is the major-mode mean. Other replicates are not written.

## Files

| Path | When |
| --- | --- |
| `export/clumpp/K<k>.indfile` | `clumpp`. One run, R=1. N rows, bar order. |
| `export/clumpp/K<k>.popq` | `clumpp`. One row per group. |
| `export/clumpp/names.txt` | `clumpp`. One row per group. Same codes at every K. |
| `export/clumpp/ids.tsv` | `clumpp`. Header `index` and `iid`. One data row per sample, bar order. |
| `export/pong/K<k>.Q` | `pong`. N lines, K numbers. |
| `export/pong/filemap.txt` | `pong`. One line per K, sorted by K. |
| `export/pong/ind2pop.txt` | `pong`. One group name per sample, bar order. |

No `drawparams` file is written. The full drawparams text is not in the excerpts used for the indfile and the popfile.

A K of 1 is still written. pong's manual says it does not accept K = 1, so stderr names `K1.Q`.

## Format

Quotes below are from the CLUMPP manual (section 4.2 indfile, section 4.3 popfile), the DISTRUCT 1.1 manual (section 2.1 population Q, section 2.2 individual Q), and the pong manual (sections 5.1 to 5.3), as copied in the source note for this step. A cell marked [UNVERIFIED] is a choice the excerpts do not settle.

### Indfile

CLUMPP: "CLUMPP expects an indfile with C x R rows and K + 5 columns per row." "Columns 1, 3, 4, and 5 are ignored by CLUMPP. Column 2 is an integer that identifies the individual. The following K columns (column 6 to column K + 5) are the membership coefficients."

DISTRUCT: "Column 2 gives a code number for the individual. Column 4 gives the code number for the population to which the individual belongs. Columns 1, 3, and 5 are ignored. Columns 6 to K + 5 show membership coefficients."

Table 4's first data row is `1   indnr   (x)   popnr    :   0.315   0.002   0.683`. The source note says Table 4's column 1 is a running index (1, 2, 3, ...). qbar writes one run, so column 1 is 1..N.

| Column | qbar writes | Source |
| --- | --- | --- |
| 1 | Running index 1..N in bar order | The source note: Table 4's column 1 is a running index (1, 2, 3, ...). |
| 2 | The same running integer as column 1, 1..N in bar order | CLUMPP: "Column 2 is an integer that identifies the individual." DISTRUCT: "Column 2 gives a code number for the individual." The DISTRUCT example puts 1297 in that column. |
| 3 | The token `1` | Both manuals ignore the column. Table 4 prints `(x)`. The DISTRUCT table prints `(3)`. Neither sentence calls it percent missing. The placeholder in the spec is `1`. [UNVERIFIED] whether `(x)` is required. |
| 4 | Group code 1..G | DISTRUCT reads this column. CLUMPP ignores it. Code 1 is the first group on the bar. The next new group is 2. Without `--groups`, every row is 1. |
| 5 | `:` | Both example rows. |
| 6 through K+5 | Aligned Q, `%.6f`, not rescaled | Both manuals. The examples use three decimals, such as 0.315. They do not state a field width. [UNVERIFIED] that a width is required. `%.6f` is the width used here. |

The iid is not written in the indfile. `ids.tsv` is one file for every K. The header line is `index`, a tab, and `iid`. Each later line is the running index, a tab, and the iid as given, in bar order. A space in the iid is kept. An empty iid is an empty field. A tab or a newline in the iid is refused, and the export directory is not created. The manuals do not describe this file. It is the map from the integer in column 2 to the sample id.

CLUMPP says it normalizes memberships and warns when the sum is outside 1 +/- 0.02. qbar does not normalize.

### Population Q file

CLUMPP: "The popfile should contain C x R rows and K + 2 columns per row." "The first column is an integer that identifies the population, and it is followed by a colon. The following K columns are the membership coefficients ... The final column gives the number of individuals of each population."

DISTRUCT: "a file with NUMPOPS rows and K + 2 columns per row." "The first column is an integer that gives a code number for the population and is followed by a colon. The next K columns are membership coefficients ... The final column gives the sample size for the population (an integer)."

The DISTRUCT caption names `casia.popq`. qbar uses `K<k>.popq`. Table 1's first row is `50:     0.646 ... 25`. Table 5's first row is `1:       0.315       0.002    0.683   10`. The colon is attached to the code.

qbar writes one row per group, in code order. R=1, so this is one block. The K numbers are the arithmetic mean of that group's plotted rows. The sum follows bar order, then divides by the count. [UNVERIFIED] the word "mean": the manuals say membership coefficients for the population, not that those coefficients are the mean of individuals. The last column is that count. The mean is not rescaled.

### Names file

DISTRUCT 1.1 section 2.3, recorded in the source note from `distruct-manual.txt` lines 190-191: "The first column contains the population code (an integer); the remaining columns contain the text that is to be printed below the figure."

`names.txt` is one line per group, code then the group name, separated by one space. A space inside the name is kept, because the remaining columns are the label text. The name is not rewritten, and stderr does not report a change. An empty name is refused. A newline in a name is refused, because pong's ind2pop quote says blank lines are not tolerated and line i belongs to individual i. The filename `names.txt` is qbar's. [UNVERIFIED] That sentence does not name the file.

### pong

"every Q matrix file in the filemap should have exactly N lines." The default is to ignore 0 leading columns. After that, only the first K columns are used. The source note states that the default delimiter is whitespace. The manual sentence that says so contains em dashes, so it was not copied verbatim. [UNVERIFIED] the exact delimiter sentence. qbar writes K numbers separated by single spaces, no leading columns. [UNVERIFIED] that a field width is required. `%.6f` is the width used here, the same width as the indfile.

Filemap, section 5.2: "The filemap must be a three-column, tab-delimited file." Column 1 is the runID. It must start with a letter, then only hyphens, underscores, letters, and numbers. Column 2 is K. Column 3 is "the path to the Q matrix, relative to the location of the filemap." A `#` starts a comment, including inside a path. qbar's run ids are `qbar_K<k>`. The path is `K<k>.Q`, in the same directory as `filemap.txt`. Lines are sorted by K. "Each value of K between Kmin and Kmax must be represented by at least one Q matrix in the filemap; if not, pong will abort." qbar does not fill a missing K. With `--no-align`, K=2 and K=4 write a filemap that has no K=3. stderr names each missing K, and the files are still written. "pong does not accept Q matrices with K = 1." Those lines are still written, and stderr says so.

ind2pop, section 5.3: "line i of this file contains the ind2pop data (i.e. population label/code/number) for the individual represented by line i of the Q matrix files. This file should contain a single column ... blank lines are not tolerated." qbar writes the group name, one line per plotted sample. `pop_names` is optional and is not written. The filemap is the only required pong input.

## Tests

`ExportTests` checks the 2 by 2 case: ids `a` and `b`, 2 data rows, 7 columns, column 2 equal to column 1, and columns 6 and 7 equal that Q. The width is K+5. The expected numbers are the matrix in the test, not a second read through the Q reader. `ids.tsv` is `index`, a tab, `iid`, then `1` and `a`, then `2` and `b`. A row that sums to 0.40 stays `0.200000 0.200000`.

A groups file sets column 4. The test sums the group means itself. `names.txt` maps those codes. The pong filemap is tab-separated, the path is `K2.Q` relative to the filemap, and the Q text is `%.6f` of the aligned rows. `clumpp,pong` and `pong,clumpp` write the same export bytes. `nope`, `clumpp,nope`, `none,clumpp`, `clumpp,`, and an empty `--export` value are errors and write no output directory. K=2 and K=4 with `--no-align` write `K2.Q` and `K4.Q` and no `K3.Q`. stderr names K 3. A clumpp-only export of that pair does not print the pong warning. K=2 and K=5 name K 3 and K 4. K=2 and K=3 do not warn. The default run, and `--export none`, write no `export` directory. Two calls write the same bytes. With `--replicates`, one `K2.Q` matches the aligned matrix and does not match the first input file. An iid `106-A` and an iid `a b` are written in `ids.tsv`, and indfile column 2 stays `1` and `2`. A tab or a newline in an iid is refused. An empty iid is kept as an empty field. An empty group name is refused. A group name `East Asia` is kept. `ind2pop.txt` is still one group name per line. `validate_config` accepts the key `export`. The YAML file test is skipped when PyYAML is not installed.
