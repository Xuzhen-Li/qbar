# F4. Simplex polygon plot

Date: 2026-10-24. This note records an optional simplex polygon plot. `--polygon` defaults to `none`. A default run writes neither `polygon_K<k>.png` nor `polygon_K<k>.tsv`. `--id-col` stays `analysis_IID`. `--group-col` stays `Dong_Grp`. `--palette` stays `science`. No new dependency.

## Mapping

Column k = 0, ..., K-1 is aligned column C(k+1). Vertex k sits at

    theta_k = pi/2 + 2 * pi * k / K
    v_k = (cos theta_k, sin theta_k)

so C1 is at the top and later vertices go counter-clockwise. That angle was approved on 2026-10-22. Math y increases upward. The PNG flips y: pixel y is `center_y - math_y * radius`.

    (x, y) = sum_k q_k * v_k

This is the Q-weighted mean of the vertex coordinates. `polygon_xy` does not divide by the row sum. A row that does not sum to 1 is drawn at that mean, and the TSV keeps the raw q.

For K=3 the vertices are not on one line. A row that sums to 1 has one q for a point in the triangle: the two coordinates plus the sum-to-1 equation are a 3 by 3 system. For K above 3 the same two coordinates plus sum-to-1 are fewer equations than columns. Different q can share one point. The K=4 rows (0.5, 0, 0.5, 0) and (0, 0.5, 0, 0.5) both land on (0, 0). The 3 by 4 system for those coordinates plus a row of ones has rank 3, which is less than 4 columns, so q is not unique. When K is above 3 the corner text is exactly `K>3: different Q can share one point`. When K is 3 or less, that text is absent. The geometry flag `many_to_one` is true only when K is above 3. The check uses that flag, not OCR.

K=1 is refused. A single vertex is not a polygon. K=2 draws the segment between the top vertex and the bottom vertex. It is not closed.

## What

`qbar.polygon.polygon_xy(q)` returns an `(n, 2)` array. It is numpy only. It allows K=1. It does not import Pillow.

`qbar.polygon.simplex(...)` returns `(image, geometry)`. Pillow is imported only inside `_draw`. Importing `qbar.polygon` does not import Pillow. Planning the geometry does not import it.

`run` calls `simplex` after the bar order is fixed, including a state replay. Q is the aligned matrix at `--polygon-k`, or the largest K when that flag is omitted. Column order, vertex colours, and vertex names match the bar for that K, including `--palette`, `--color`, `--color-file`, and colours and names from `--state`. Rows are that bar order. Values are not rescaled. With `--replicates`, the matrix is the aligned one, which is the major-mode mean when that K has more than one file.

The alignment mask does not drop rows. The bar draws every row of the aligned matrix, and this figure uses the same rows. `--align-mode core` does not remove a low-qmax sample from the TSV.

`--vector` does not write `polygon_K<k>.pdf` or `polygon_K<k>.svg`, including when the bar figures are vectors.

The two flags are documented here and in `docs/cli.md`. The README option list does not name them yet.

## Canvas

The plot square is 1200 px. Margins are left 24, top 48, and bottom 24, plus a 320 px legend gutter. The default canvas is 1544 by 1272 px. If the group legend is taller than the square, the canvas grows. The background is white.

Vertices sit on a circle of radius 420 px, centred in the square, so the names sit outside the polygon and inside the square. Each vertex is a filled disc of radius 7 px in that cluster's bar colour, with the bar legend name beside it. A name wider than the space beside that vertex is truncated with `...`. A left label stops at canvas x=4, a right label stops 4 px before the gutter, and a top or bottom label is centred and limited to the plot square width. One stderr note names each truncated vertex and says the full name is in the bar legend. `truncated_vertices` lists those columns, and each vertex stores `truncated` and `label_full`. The outline is `#b0b0b0`. For K=2 the outline is the segment. For K above 2 it is the closed polygon.

Point radius is 3 px. When N is above 5000 it is 2 px. N = 5000 stays at 3 px. Points are opaque RGB. Alpha is not used, so a later disc replaces the pixels under it. Groups are painted in the order groups first appear in the bar row order. A later group covers an earlier group where they overlap. Inside a group, samples follow bar order, and a later sample covers an earlier one. Vertex discs are painted after the points.

The design figure paints every sample the same blue and has no groups, so it does not define a per-group colour. Points are coloured by group with the matplotlib tab10 hex list, the same values as `plot_static.TAB10_PALETTE`:

`#1f77b4` `#ff7f0e` `#2ca02c` `#d62728` `#9467bd` `#8c564b` `#e377c2` `#7f7f7f` `#bcbd22` `#17becf`

Group i in bar group order uses colour `tab10[i % 10]` and marker cycle `i // 10`: 0 circle, 1 square, 2 triangle pointing up, 3 diamond, then the shapes repeat. The square side equals the circle diameter. The diamond reaches that same distance on each axis. The triangle is equilateral and points up. Its width equals the circle diameter, so its height is radius times sqrt(3), and it is centred vertically on the point. The legend draws that marker in the group's colour. More than 10 groups add `Colours repeat after 10 groups; marker shape changes.` That sentence is stored as one string and drawn on two lines, split after the semicolon, so it fits the 320 px gutter. More than 40 groups also add `Shapes repeat after 40 groups.` Ten groups stay circles and add no note. Forty groups use each shape once and do not add the shape note. A run with no groups file paints every point `#333333` as a circle. The legend label is that single rest name when every row shares it, and `samples` when the labels differ. A missing id in a groups file is the rest name and is a real group, so it uses tab10 and the marker for that group's place in bar order. Each legend entry and each point has a `marker` field.

The picture is drawn at 2x and resized with Pillow `Image.Resampling.LANCZOS`. The filter is fixed. There is no clock and no random source in the draw. Two runs in one environment write the same PNG bytes. The label font is the first face `plot_static.load_font` finds. A different face can change the PNG bytes. The geometry and the TSV do not use the font.

## Outputs

`polygon_K<k>.png` and `polygon_K<k>.tsv` are written in the output directory only when `--polygon simplex` is set and the run finishes. The table header is `iid`, `group`, `x`, `y`, then `q1` through `qK` in aligned column order. x, y, and each q use `%.6f` of the math coordinates and the raw q. The file is UTF-8, uses newline `\n`, and ends with a newline. Row order is the bar order, which is the order passed in. Paint order can differ from that row order. A renamed legend stays on the vertex label. It does not rename `q1` through `qK`.

`polygon` and `polygon_k` are config keys. Neither is a file path. `polygon` is `none` or `simplex`. `polygon_k` is an integer, or null when the flag is omitted. Null in `config_resolved.json` means the largest K at runtime. The run does not rewrite that null.

A bad `--polygon-k` is raised before the output directory is created, including when `--polygon` is `none`. K=1 is refused only when `--polygon` is `simplex` and the chosen K is 1. A tab, newline, or carriage return in an iid, a group, or a legend name is refused before the directory is created.

## Errors

| Case | What the message names |
| --- | --- |
| `--polygon` is not `none` or `simplex` | the value |
| `--polygon simplex` and the chosen K is 1 | that K=1 is refused |
| `--polygon-k` is not in the run | that K and the available K |
| The matrix is not 2-d | the dimension count |
| K is below 2 | the column count |
| The id list length does not match the rows | both counts |
| The group list length does not match the rows | both counts |
| The colour list length does not match K | K and the count |
| The legend length does not match K | K and the count |
| `k` does not match the column count | both numbers |
| An iid, group, or legend name contains a tab or a newline | the field kind and the plotted row |

Cross-K alignment still requires consecutive K. A gap is reported by that existing check before the polygon K check.

The geometry tests compute the coordinates in the test, from the same angle formula, and do not read them back from a qbar table. K=4 rows (0.5, 0, 0.5, 0) and (0, 0.5, 0, 0.5) both give (0, 0) within 1e-12. K=3 (0.7, 0.2, 0.1) gives x = -sqrt(3)/20 and y = 0.55. K=3 (1, 0, 0) gives (0, 1). For random K=3 rows that sum to 1, solving the 3 by 3 system of the two coordinates plus sum-to-1 returns the original q. The K=4 coordinate-plus-ones matrix has rank 3, which is less than 4, and a nonzero kernel maps two different q onto (0, 0). For K=3 the C2 vertex has negative x, C1 is at the top, and successive vertices turn counter-clockwise. Pixel y of C1 is above the other vertices because the PNG flips y.

A 60-character name at K=4 truncates C2 and C4. At K=6 it truncates C2, C3, C5, and C6. The geometry marks those vertices, the drawn text ends with `...`, and one stderr note names them. Column 0 stays white, and the right-hand labels do not paint at or past the gutter. Short names such as C1 are not truncated and print no note. K=1 exits with the qbar message and does not create the output directory. `--polygon-k` outside the run names the available K, for both `simplex` and `none`, and does not create the directory. K=2 points lie on the segment. `corner_text` is the sentence when K is above 3 and empty when K is 3 or 2. The TSV header and `%.6f` values match the independent coordinates and the aligned q, including a row that does not sum to 1. Omitting `--polygon-k` writes only the largest K. Setting it writes only that K. After a non-identity alignment permutation the vertex colours equal the bar palette for that K, including `--color` and `--state` names. A default run, and an explicit `--polygon none`, write no polygon files. Two `simplex` calls and two command-line runs write the same PNG bytes. `--vector both` writes a bar SVG and does not write a polygon PDF or SVG. A tab in an iid is refused.
