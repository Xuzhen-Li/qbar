# F10. Static page

Date: 2026-10-24. This note records the first half of the static page, including the review fix that stopped loading Pyodide from a CDN at runtime. The page is not published. Hosting is a later decision. Command-line defaults are unchanged. `--palette` stays `science`. `--id-col` stays `analysis_IID`. `--group-col` stays `Dong_Grp`. `--align-method` stays `greedy`. `--vector` stays `off`. No new Python dependency.

## Route

The page runs the unchanged qbar package inside Pyodide 314.0.7. There is no JavaScript port of the aligner or the plotter. The source is under `web/`. `tools/build_web.py` builds a wheel with `pip wheel --no-deps` into `web/dist/` and writes `manifest.json` with the wheel file name and its sha256. The same build downloads the pinned runtime into `web/dist/pyodide/` and checks it against `web/pyodide-pins.json`. That directory is git-ignored and is not committed.

The documented way to use the page, after that build, is:

```bash
python -m http.server --directory web 8000
```

Then open `http://127.0.0.1:8000/`.

Checked on 2026-10-24. The newest stable Pyodide release whose lock file lists numpy, scipy, and pillow is 314.0.7. The pins use the jsDelivr directory for that version. The download is 9 files and 31674817 bytes.

## What is verified

At build time, every file named in `web/pyodide-pins.json` is checked by sha256 and size. The bytes are written under a temporary name and renamed only after that check. A file that already exists and does not match is left in place and the build stops. Each package wheel's pin sha256 is also required to equal the sha256 in the verified `pyodide-lock.json`. A second build, when the files already match, downloads nothing.

At load time in the browser, `indexURL` is `./dist/pyodide/` on this same origin. The page makes no third-party request. Pyodide 314.0.7 `loadPyodide` has no `checkIntegrity` option. `loadPackage` takes `checkIntegrity`, the default is true, and the page passes true. That checks each package wheel against the sha256 in the lock file. The runtime files are not part of that package check. Their check is the build-time pin.

In Node, this Pyodide build's file reader does not apply the integrity argument. The cross-check script checks the pin file before it loads the directory.

qbar imports numpy, scipy, and Pillow. The page also loads micropip and installs the local wheel with dependencies turned off. The page does not use a config file, so PyYAML is not loaded.

## What the page runs

The page calls `qbar.cli.build_parser` and then `qbar.api.run`. `cli.main` is not used. Uploaded files are written under `/in` using base names only. The output directory is `/out`. The page passes `--editor` so the package writes `state.json`. It does not pass `--palette` or the other flags, so those stay at the command-line defaults. The form supplies the align method, `--vector` when it is not `off`, and the id and group column names when a groups file is set. Blank column names keep `analysis_IID` and `Dong_Grp`.

After a successful run the background thread calls `qbar.state.colours_tsv` and writes `colours.tsv`. Downloads are one file each: PNG per K, PDF or SVG when `--vector` is not `off` and the run finishes, `order.tsv`, `colours.tsv`, and `state.json`, plus the other files the run wrote. A zip is not built.

The equivalent-command box is that same argument list with base names, without `--editor`, plus `--state state.json`.

Pyodide runs in a background thread so the page stays responsive. The status line is one of: loading, ready, running, done, error.

The wheel name in the manifest must be a single file name before the page reads the wheel. It checks the wheel sha256 against the manifest before install. A mismatch is an error.

The size limit is 200 * 1024 * 1024 bytes, which is 209715200. The message names the total and that limit.

K from and K to must both be integers when any Q file name includes a K. A blank value, or a value that is not an integer, is an error and the run does not start. File names with no K have no range, and every such Q file is used.

A Q row count that does not match the sample list is qbar's own message. The English text names both counts: the Q row count and the sample-list count. The page shows that text as text.

## Cross-check

`tools/web_check.mjs` loads Pyodide from the pinned directory the build wrote. The script itself does not use the network. It checks those files against `web/pyodide-pins.json` first. It installs the wheel built for this tree, runs qbar with the same argument list the page builds, and compares that output with a command-line run through `tools/compare_outputs.py`. A difference that is not on the allow list exits nonzero. The allow list is: `state.json` may differ only in `git_commit`, and the command-line run records the checkout HEAD while the wheel records `unknown`; `editor.html` may differ only in that field; `args.txt` may differ in paths; PNG bytes may differ only when the pixels match; PDF bytes may differ only when the reason names the Pillow version difference. A PNG whose pixels differ fails.

The fixture was the bundled demo, limited to filename K 2 and K 3, with its sample file and groups file. The id and group column names were the names in that groups file. The method was `greedy`. `--vector` was `off`. The argument list included `--editor`, as the page does. The check also mounts the first existing TrueType candidate so the comparison is about the drawing, not a missing font. The page does not mount a font.

`PYTHONHASHSEED` was 0. The runtime reported hash randomization 0.

Identical: `align.tsv`, `blocks.tsv`, `colours.tsv`, `order.tsv`, `perm_K2.tsv`, `perm_K3.tsv`.

`state.json` differed only in `git_commit`. `editor.html` differed only in that field. `args.txt` differed because one side uses host paths and the other uses `/in` and `/out`.

PNG bytes differed and the pixels matched for `bar_K2.png`, `bar_K3.png`, and `panel.png`. Pillow in Pyodide is 12.2.0. The command-line comparison used Pillow 11.3.0, Python 3.9.6, numpy 2.0.2, and scipy 1.13.1. PDF bytes for `bar_K2.pdf`, `bar_K3.pdf`, and `panel.pdf` differed with that Pillow reason.

The check exits 0 only when the allow list covers every `compare_outputs.py` difference.

A browser PNG will not match those pixels, because the page has no TrueType file and PNG falls back to Pillow's built-in font.
